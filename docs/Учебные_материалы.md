## Введение в машинное обучение

Идентификатор: mat_01. Чтение около 4 мин; практика около 10 мин.

### 1. Что значит «обучить модель»

Машинное обучение позволяет находить закономерности в примерах. Вместо перечисления всех правил разработчик выбирает способ представления объектов и алгоритм, который подбирает параметры по данным. **Объект** — отдельный случай, **признаки** — его измеримые характеристики, **целевая переменная** — ответ, который нужно предсказывать.

При обучении с учителем известны и признаки, и правильные ответы обучающих примеров. В задаче классификации ответом служит категория: например, вид документа. В регрессии требуется число: например, длительность выполнения задания. Наличие числа в таблице само по себе ещё не делает задачу регрессией: числовые коды категорий остаются категориями.

### 2. Как поставить учебную задачу

Предположим, нужно заранее предложить студенту дополнительное занятие. Объектом будет участие одного студента в конкретном курсе. Признаками могут стать число отправленных заданий и доля посещённых занятий к выбранному дню. Ответом — заранее определённый исход курса. Данные должны отражать только сведения, доступные в момент прогноза. Итоговая оценка, внесённая после окончания курса, не подходит как признак раннего прогноза: это утечка информации.

Такая модель оценивает закономерности в наблюдениях, а не способности человека. Для реального применения нужно отдельно проверить качество, ошибки и применимость данных к новой группе.

### 3. Обучение и проверка

Обычный порядок работы: определить задачу, подготовить признаки, разделить примеры, обучить модель и оценить её на отложенных данных. **Обучающая выборка** нужна для подбора параметров; **валидационная** — для выбора настроек; **тестовая** — для итоговой оценки выбранного решения. Один и тот же студент не должен случайно оказаться с почти одинаковыми записями по обе стороны разбиения, если это искажает проверку.

Переобучение возникает, когда модель слишком хорошо подстраивается под особенности обучающих примеров и хуже работает на новых. Поэтому высокая точность на обучении ещё не доказывает полезность модели.

### 4. Разобранный пример

Из десяти новых объектов классификатор правильно определил восемь категорий. Доля правильных ответов, или accuracy, равна `8 / 10 = 0,8`, то есть 80 %. Это показатель на данных, а не правило начисления учебных баллов.

Если редкий важный исход встречается только у одного объекта из десяти, постоянный ответ «обычный исход» уже даст 90 % accuracy. Чтобы оценить такой классификатор, потребуется изучить ошибки по классам, в том числе пропуски редкого исхода. Одна цифра не описывает всю задачу.

### 5. Типичные ошибки

- Подменять признаки готовым итоговым ответом.
- Проверять качество только на данных обучения.
- Считать любую числовую переменную непрерывным результатом.
- Переносить модель на другую аудиторию без отдельной оценки.

### 6. Что запомнить

Классификация предсказывает категорию, регрессия — числовой результат. Признаки описывают объект и должны быть доступны до ответа. Качество на новых данных проверяется отдельно. В этом приложении переход между темами определяется правилом по тесту, а модель OULAD находится в самостоятельном аналитическом разделе.

## Как работают деревья решений

Идентификатор: mat_02. Чтение около 4 мин; практика около 10 мин.

### 1. Узлы, ветви и листья

**Дерево решений** последовательно проверяет условия над признаками объекта. Начальный узел называется корнем. Внутренний узел задаёт проверку, ветви соответствуют её исходам, а конечный узел — **лист** — содержит предсказание. Путь от корня до листа можно прочитать как цепочку правил «если …, то …».

Деревья применяются и для классификации, и для регрессии. В первом случае лист задаёт класс или оценки вероятностей классов, во втором — числовой прогноз. Набор правил, написанных вручную, помогает понять устройство дерева, но обучаемая модель подбирает разбиения по примерам.

### 2. Как выбираются условия

Во время обучения алгоритм перебирает допустимые разбиения. Для классификации оценивается, насколько группы после разбиения становятся более однородными по ответам. Например, условие по числу выполненных заданий полезно, если после него лучше отделяются разные классы. Процесс повторяется внутри получившихся частей, пока не сработает условие остановки.

Узлы не обязаны проверять разные признаки: один числовой признак может использоваться несколько раз с разными порогами. Глубина дерева показывает длину пути от корня к наиболее далёкому листу. Очень глубокое дерево может запоминать редкие особенности обучающих записей.

### 3. Разобранный пример

Пусть демонстрационное правило использует число заданий и последний процент теста:

```python
def recommendation(tasks, score):
    if tasks < 3:
        return "повторить основы"
    if score < 80:
        return "выполнить практику"
    return "перейти дальше"

print(recommendation(2, 90))
print(recommendation(4, 60))
print(recommendation(4, 100))
```

Ответы: «повторить основы», «выполнить практику», «перейти дальше». Первый объект не проверяет условие по проценту: он сразу попадает в лист первой ветви. Изменение неиспользованного признака на этом пути не меняет ответ. Этот пример иллюстрирует обход дерева; условия здесь выбраны вручную и не являются обученной моделью.

### 4. Сложность и переобучение

Дерево с отдельным листом почти для каждого примера может показать прекрасный результат на обучении и ошибаться на новых данных. Ограничение максимальной глубины и минимального числа объектов в листе уменьшает сложность. Слишком сильное ограничение, наоборот, может не позволить уловить полезные закономерности — это недообучение.

Настройки сравнивают на валидационных данных. После выбора решения качество оценивают на отдельной тестовой выборке. Нельзя объявлять определённую глубину «лучшей для всех задач» без проверки.

### 5. Типичные ошибки

- Считать лист ещё одним вопросом: в листе уже формируется ответ.
- Полагать, что большая глубина всегда повышает качество на новых данных.
- Путать ручную схему решений с моделью, обученной по примерам.
- Настраивать дерево много раз по итоговой тестовой выборке.

### 6. Что запомнить

Узел проверяет условие, ветвь выбирает направление, лист выдаёт предсказание. Ограничение глубины помогает контролировать сложность. Полезность условий и настроек подтверждается на новых данных, а не внешним видом дерева.

## Метод случайного леса

Идентификатор: mat_03. Чтение около 4 мин; практика около 10 мин.

### 1. Зачем объединять модели

Одиночное дерево может заметно менять ответ после небольшого изменения обучающих данных. **Случайный лес** объединяет множество деревьев решений в ансамбль. Если ошибки деревьев не полностью совпадают, общий ответ может оказаться устойчивее ответа отдельной модели. Поэтому до леса полезно изучить узлы, листья и переобучение дерева.

Разнообразие создаётся несколькими механизмами. В обычном варианте каждое дерево получает случайную выборку обучающих объектов с возвращением: одни записи могут повториться, другие — не попасть в неё. При поиске разбиения рассматривается случайное подмножество признаков. Это мешает всем деревьям каждый раз выбирать одинаковые условия.

### 2. Два способа объединения

Для классификации удобно начать с учебной схемы **голосования**: выбирается класс, за который высказалось большинство деревьев. Например, ответы `А, Б, А, А, Б` дают итог `А`. В конкретной библиотеке реализация может усреднять оценки вероятностей классов; именно так устроен классификатор случайного леса scikit-learn. При чистых листьях примера эти способы совпадают, в общем случае их следует различать.

Для регрессии объединяются числовые прогнозы. Если три дерева предсказали 10, 14 и 12, среднее равно `(10 + 14 + 12) / 3 = 12`. Выбор максимума 14 не является обычным правилом ответа леса.

### 3. Разобранный пример

```python
from collections import Counter

classes = ["А", "Б", "А", "А", "Б"]
votes = Counter(classes)
winner = votes.most_common(1)[0][0]
values = [10, 14, 12]
prediction = sum(values) / len(values)
print(winner)
print(prediction)
```

Программа выведет `А` и `12.0`. Она демонстрирует объединение готовых ответов, но не обучение леса. Если число голосов совпало, требуется заранее определённое правило выбора; молча считать любой результат большинства корректным нельзя.

### 4. Что проверять при обучении

Число деревьев, глубина, размер листьев и число рассматриваемых признаков влияют на качество и затраты. Больше деревьев обычно увеличивает время и память, но не гарантирует полезного улучшения для каждой задачи. При наличии случайности фиксированное зерно помогает воспроизводить эксперимент.

Разделение обучающих и тестовых данных сохраняется и для ансамбля. Случайный лес не устраняет утечку информации и не превращает неподходящий набор признаков в достоверный прогноз. Сравнивать его с простым базовым решением нужно на одной схеме проверки.

### 5. Типичные ошибки

- Обучить несколько полностью одинаковых деревьев и ожидать большого выигрыша от объединения.
- Для числовой задачи выбирать самый большой прогноз вместо среднего.
- Оценивать модель только по её ответам на обучающих примерах.
- Приписывать каждому дереву независимость ошибок: на практике сходство остаётся.

### 6. Что запомнить

Лес состоит из деревьев. Случайность в объектах и признаках поддерживает разнообразие. Учебная схема классификации — голосование; регрессии — усреднение. Способ объединения вероятностей и обработку равенства ответов следует уточнять в документации используемой библиотеки.

## Основы линейной регрессии

Идентификатор: mat_04. Чтение около 4 мин; практика около 10 мин.

### 1. Задача числового прогноза

**Линейная регрессия** описывает числовой ответ через линейную комбинацию признаков. Для одного признака модель записывается как `ŷ = b0 + b1 × x`, где `ŷ` — прогноз, `x` — значение признака, `b0` — свободный член, `b1` — коэффициент. Для нескольких признаков добавляются соответствующие слагаемые.

В учебном примере `ŷ = 30 + 5 × hours` модель предсказывает результат по числу часов подготовки. Коэффициент 5 означает изменение прогноза на пять единиц при увеличении hours на один час в рамках этой модели. Это описание зависимости, а не доказательство эффекта дополнительного часа подготовки.

### 2. Откуда берутся коэффициенты

Обучаемая модель подбирает коэффициенты по примерам с известными ответами. В обычном методе наименьших квадратов уменьшается сумма квадратов разностей между наблюдаемыми значениями и прогнозами на обучении. Разность «наблюдение минус прогноз» называют остатком.

Признаки могут иметь разные единицы измерения. Поэтому численное значение коэффициента нельзя интерпретировать без масштаба признака. Свободный член описывает прогноз при нулевых признаках, но такой случай может находиться за пределами разумного диапазона данных.

### 3. Разобранный расчёт

Для `ŷ = 2 × x + 3` и `x = 4` получаем `2 × 4 + 3 = 11`. Если наблюдаемый ответ равен 13, остаток составляет `13 − 11 = 2`, абсолютная ошибка — 2, квадрат ошибки — 4.

```python
x = [1, 2, 4]
y = [5, 8, 13]
predicted = [2 * value + 3 for value in x]
mae = sum(abs(actual - guess)
          for actual, guess in zip(y, predicted)) / len(y)
print(predicted)
print(round(mae, 2))
```

Программа выдаст `[5, 7, 11]` и `1.0`. Средняя абсолютная ошибка вычислена как `(0 + 1 + 2) / 3`. Здесь коэффициенты заданы вручную, поэтому пример проверяет применение формулы и расчёт ошибки, а не процесс обучения.

### 4. Проверка качества и ограничения

Качество выбранной модели оценивают на отдельной тестовой выборке. Полезно сравнить её с простым постоянным прогнозом и посмотреть, где ошибки особенно велики. Усложнение модели не следует оценивать только по улучшению на обучении.

Линейная зависимость может быть недостаточным описанием. Прогноз далеко за пределами наблюдавшихся значений называется экстраполяцией и требует осторожной интерпретации. Например, формула для обычного времени подготовки не гарантирует реалистичный ответ при сотнях часов.

### 5. Типичные ошибки

- Путать коэффициент с самим признаком или целевым ответом.
- Забывать свободный член при подстановке.
- Объявлять корреляционную зависимость причинной: общие факторы могут влиять на обе величины.
- Выбирать настройки по тестовой выборке и затем считать её независимой проверкой.

### 6. Что запомнить

Регрессия предсказывает число. Коэффициенты обучаемой модели подбираются по данным. Прогноз получается подстановкой признаков в формулу, ошибка — сравнением с известным ответом. Найденная зависимость сама по себе не устанавливает причину.

## Переменные и типы данных

Идентификатор: python_01. Чтение около 4 мин; практика около 10 мин.

### 1. Имена и значения

В Python переменная связывает имя с объектом. Запись `count = 5` создаёт связь имени count с целым числом. Операция `=` выполняет присваивание, а `==` сравнивает значения. Тип относится к объекту: одно имя позже можно связать с другим значением, но при написании понятной программы лучше сохранять ожидаемый смысл переменной.

Основные типы для первых задач: `int` — целые числа, `float` — числа с плавающей точкой, `str` — строки, `bool` — логические значения. Строка `"5"` отличается от числа `5`: выражение `"5" + "2"` даёт `"52"`, а `5 + 2` — `7`. Преобразование `int("5")` возвращает число, если текст имеет допустимый формат.

### 2. Последовательности и списки

Список `list` хранит упорядоченную изменяемую последовательность. Индекс первого элемента равен нулю. У списка `[40, 80, 100]` обращение `[1]` выбирает 80. Метод append добавляет значение в конец. Список не обязан содержать только числа, однако единообразные данные проще обрабатывать.

Изменяемость имеет значение при присваивании списка другому имени: `second = first` не создаёт независимую копию. Оба имени относятся к тому же списку. Для плоского списка `first.copy()` создаёт отдельную внешнюю последовательность; вложенные изменяемые объекты требуют отдельного внимания.

### 3. Разобранный пример

```python
student = "Анна"

scores.append(100)
```

Здесь используется среднее трёх результатов ради знакомства с типами. В самом учебном приложении тема осваивается по лучшей успешной попытке, поэтому этот пример не описывает его серверное правило.

### 4. Отступы и блоки

После строки с `if`, `else`, `for` или `def` двоеточие открывает блок. Вложенные инструкции записываются с одинаковым отступом; в примерах используются четыре пробела. Отступ — часть синтаксиса, а не просто украшение. Смешивание разных уровней может изменить смысл или привести к ошибке.

## Функции и повторное использование кода

Идентификатор: python_02. Чтение около 4 мин; практика около 10 мин.

### 1. Зачем выделять функцию

Функция объединяет действие с понятным именем, входами и результатом. Она позволяет использовать одну логику в разных местах и проверять её отдельно. Определение начинается с `def`, после имени указываются параметры, а тело записывается с отступом. Само определение не выполняет тело: нужен вызов.

**Параметр** — имя во время определения, **аргумент** — конкретное значение при вызове. В `def double(value)` параметр называется value; в `double(7)` аргументом служит 7. Имена параметров должны объяснять, какие данные ожидаются.

### 2. Возврат и область видимости

`return` завершает текущий вызов и передаёт результат вызывающему коду. Дальнейшие инструкции того же пути после return не выполняются. Если функция не возвращает значение явно, результатом будет `None`. Вывод через print и возврат через return — разные действия: напечатанное число само по себе не становится возвращённым значением.

Локальные имена обычно принадлежат конкретному вызову. Их не нужно объявлять глобальными ради передачи результата. Входы лучше получать через параметры, а результат — через return: так легче понять зависимости и написать тест.

### 3. Разобранный пример

```python
def mean_score(scores):
    if not scores:
        return None
    total = sum(scores)
    return total / len(scores)

first = mean_score([40, 80, 100])
second = mean_score([])
print(round(first, 2))
print(second)
```

Ответы: `73.33` и `None`. У первого вызова total равен 220, длина — 3. Во втором срабатывает ранний возврат, поэтому деления на ноль нет. Локальное имя total используется внутри функции; снаружи доступны результаты first и second.

Выбор None для пустого списка — явное решение этого примера. Другая программа может поднимать исключение. Главное — определить поведение и согласовать его с вызывающим кодом, а не маскировать отсутствие данных обычной оценкой 0.

### 4. Повторное использование и проверка

Функцию mean_score можно использовать для нескольких студентов, передавая разные списки. Она не спрашивает данные через input и не рисует страницу, поэтому вычисление легко проверить без браузера. Отдельная функция интерфейса уже решает, как показать None или округлить число.

Для проверки нужны обычный набор, один элемент и пустой набор. Если далее добавляется запрет отрицательных значений, изменяется контракт функции и соответствующие проверки. Одна функция не должна одновременно вычислять среднее, обращаться к сети и создавать отчёт без необходимости.

### 5. Типичные ошибки

- Забыть скобки вызова: имя функции и результат вызова различаются.
- Заменить return печатью и затем получить None в вычислениях.
- Рассчитывать, что локальное имя автоматически доступно везде.
- Менять переданный список неожиданно для вызывающего кода.

### 6. Что запомнить

def определяет функцию, параметры принимают входы, return передаёт результат. Хорошая функция имеет ясную ответственность и определённое поведение на крайних входах. Именно такая структура позволяет повторно использовать и проверять код.

### Ориентир для самопроверки

Один вариант: `return sum(1 for score in scores if score >= 80)`. Ожидаются 2, 0 и 0. Параметр scores получает переданный список, return передаёт число вызывающему коду. Если вместо возврата только напечатать число, результатом вызова станет None.

## Таблицы и связи

Идентификатор: databases_01. Чтение около 4 мин; практика около 10 мин.

### 1. Записи и поля

Реляционная база хранит связанные данные в таблицах. **Строка** представляет запись, **столбец** — её поле. Таблица students может содержать id, full_name и group_id. Порядок строк в хранилище не заменяет явно заданный порядок результата запроса.

**Первичный ключ** однозначно отличает запись. Для учебного справочника удобно использовать стабильный числовой id. Имя студента плохо подходит в качестве ключа: у разных людей бывают одинаковые имена, а написание может измениться.

### 2. Как связать студента и группу

Если в каждой записи студента повторять название группы и всю информацию о программе, изменение одного названия потребует обновить много строк. Вместо этого создают справочник groups, а в students хранят ссылку group_id. Одна группа может иметь много студентов — это связь «один ко многим».

**Внешний ключ** описывает ссылку на допустимую запись родительской таблицы. Ограничение помогает обнаружить попытку назначить несуществующую группу. Для SQLite контроль внешних ключей следует явно включать для каждого соединения. Связь в схеме и её фактическая проверка должны быть согласованы.

### 3. Разобранный пример SQLite

```sql
PRAGMA foreign_keys = ON;

CREATE TABLE groups (
    id INTEGER PRIMARY KEY,
    name TEXT NOT NULL UNIQUE
);

CREATE TABLE students (
    id INTEGER PRIMARY KEY,
    full_name TEXT NOT NULL,
    group_id INTEGER NOT NULL REFERENCES groups(id)
);

INSERT INTO groups (id, name) VALUES (1, 'ПИ-21');
INSERT INTO students (id, full_name, group_id)
VALUES (101, 'Анна Белова', 1);

SELECT full_name, group_id FROM students;
```

Результат выборки — одна запись: «Анна Белова», 1. Сначала создаётся родительская группа, затем студент с её ключом. При включённой проверке внешнего ключа значение group_id = 999 будет отклонено, если такой группы нет. Сама ошибка не создаёт недостающий справочник автоматически.

### 4. Что делает SELECT

SELECT получает представление данных. Можно перечислить нужные поля или использовать `*` для всех столбцов. Выборка не означает удаление или изменение исходных строк. Для обновления и удаления существуют другие операции, которые требуют собственного условия и проверки.

Для связи «многие ко многим», например групп и дисциплин, добавляют промежуточную таблицу с двумя ссылками. Это позволяет включить одну дисциплину в планы нескольких групп и избежать хранения списка идентификаторов в одной текстовой ячейке.

### 5. Типичные ошибки

- Использовать изменяемое имя вместо устойчивого ключа.
- Повторять сведения о группе в каждой записи студента.
- Считать, что столбец с названием group_id сам включает проверку внешнего ключа.
- Полагаться на случайный порядок строк без ORDER BY.

### 6. Что запомнить

Строка — запись, столбец — поле. Первичный ключ идентифицирует запись, внешний связывает её с другой. Справочники уменьшают дублирование. SELECT читает данные; ограничения обеспечивают правила их согласованного хранения.

### Самостоятельная работа

В отдельной учебной SQLite выполните схему из конспекта, добавьте группу ИВТ-21 с id=2 и студента с group_id=2. Получите имена всех студентов. С включёнными внешними ключами проверьте отклонение group_id=999.

### Ориентир для самопроверки

Сначала должна существовать родительская группа. SELECT full_name FROM students возвращает имена добавленных записей. При PRAGMA foreign_keys=ON ссылка на отсутствующий id=999 отклоняется. Название группы хранится один раз в справочнике, у студента — её ключ.

## Выборка и объединение данных

Идентификатор: databases_02. Чтение около 4 мин; практика около 10 мин.

### 1. Получить нужные строки

Запрос SELECT описывает, какие данные нужны. FROM задаёт исходные таблицы, WHERE фильтрует строки, ORDER BY определяет порядок результата. Например, условие `score >= 80` оставляет успешные результаты. Сортировка по убыванию задаётся DESC, по возрастанию — ASC.

Это логические части запроса, а не инструкция вручную обходить файл в указанной последовательности. План выполнения выбирает система управления базой. При равных значениях основного ключа сортировки дополнительное поле делает порядок определённым.

### 2. Связать таблицы и посчитать итоги

JOIN объединяет строки по условию. Для students и groups обычно сравнивают `students.group_id = groups.id`. INNER JOIN сохраняет только совпавшие пары; LEFT JOIN оставляет все строки слева, даже когда справа соответствия нет.

COUNT(*) считает строки полученного набора. GROUP BY формирует группы для итоговых вычислений, а HAVING фильтрует уже вычисленные группы. В отличие от COUNT(*), `COUNT(column)` не считает NULL в указанном столбце. Это различие важно для LEFT JOIN и групп без студентов.

### 3. Разобранный пример

Предположим, группы имеют id 1 и 2, а три записи students содержат пары «Анна, 1», «Борис, 1», «Вера, 2».

```sql
SELECT g.name, COUNT(s.id) AS student_count
FROM groups AS g
LEFT JOIN students AS s ON s.group_id = g.id
GROUP BY g.id, g.name
ORDER BY student_count DESC, g.name ASC;
```

Если названия групп ПИ-21 и ИВТ-21, результатом будут ПИ-21 — 2 и ИВТ-21 — 1. Если добавить группу без студентов, она получит 0: COUNT(s.id) пропускает NULL в пустом соответствии. COUNT(*) в такой строке дал бы 1 и исказил бы нужный смысл подсчёта.

Запрос списка студентов одной группы выглядит так:

```sql
SELECT full_name
FROM students
WHERE group_id = 1
ORDER BY full_name ASC;
```

Получатся Анна и Борис. Сам справочник групп при этом не изменяется.

### 4. Параметры и точность результата

В приложении значения пользователя передают как параметры запроса. В Python с sqlite3 используется `WHERE group_id = ?` и отдельный кортеж значений. Соединение пользовательского текста со строкой SQL может нарушить запрос и создать уязвимость.

При соединении нескольких связей «один ко многим» одна исходная запись может появиться несколько раз. Поэтому нужно сначала определить единицу подсчёта: студенты, попытки или пары. COUNT(*) не угадывает, что именно автор имел в виду.

### 5. Типичные ошибки

- Использовать ORDER BY как средство фильтрации.
- Соединять таблицы без нужного условия и получать лишние пары.
- Считать COUNT(*) и COUNT(s.id) равнозначными при LEFT JOIN.
- Подставлять введённое имя в SQL простой конкатенацией строк.

### 6. Что запомнить

WHERE выбирает строки, JOIN связывает таблицы, GROUP BY собирает группы, COUNT вычисляет количество, ORDER BY сортирует итог. Перед написанием запроса сформулируйте, что должна представлять одна строка результата.

### Самостоятельная работа

Добавьте в учебную базу третью группу без студентов. Напишите запрос, который показывает все группы и количество студентов, включая ноль. Объясните выбор LEFT JOIN и COUNT(s.id). Затем выведите только группы с двумя и более студентами.

### Ориентир для самопроверки

Используйте LEFT JOIN students s ON s.group_id=g.id, GROUP BY g.id,g.name и COUNT(s.id). Для итогового ограничения добавьте HAVING COUNT(s.id)>=2. INNER JOIN потеряет пустую группу, а COUNT(*) при LEFT JOIN посчитает строку пустого соответствия как единицу.

## HTTP и клиент-серверное взаимодействие

Идентификатор: web_01. Чтение около 4 мин; практика около 10 мин.

### 1. Запрос и ответ

В клиент-серверной модели клиент обращается к сервису, сервер обрабатывает запрос и формирует ответ. Браузер часто выступает клиентом, но запрос может отправлять и другая программа. HTTP описывает обмен сообщениями прикладного уровня: метод, адрес ресурса, заголовки и, при необходимости, тело.

Ответ содержит код состояния, заголовки и необязательное тело. Тело может быть HTML-страницей, JSON, изображением или другим представлением. Сервер не обязан отвечать страницей только потому, что запрос отправлен из браузера.

### 2. Методы и состояния

GET обычно получает представление ресурса и по своему смыслу не должен выполнять запрошенное изменение данных. POST отправляет данные для обработки, например ответы теста. Метод выбирают по смыслу операции, а не по длине адреса. POST сам по себе не защищает пароль и не шифрует тело запроса.

Код 200 обычно означает успешную обработку, 201 — создание ресурса, 404 — отсутствие запрошенного ресурса. Код 401 связан с отсутствующей или неподходящей аутентификацией, 403 — с запретом доступа. Ошибки класса 5xx относятся к обработке на стороне сервера. Конкретный API должен документировать свои состояния.

```http
{"material_id": "python_01", "questions": []}
```

### 4. Канал и содержимое

HTTPS использует TLS для защиты обмена между конечными точками соединения, включая шифрование и проверку сертификата в обычной веб-модели. Это не доказывает честность владельца страницы и не исправляет ошибки его программы. Поддельный сайт тоже может иметь HTTPS.

В локальной демонстрации адрес localhost относится к тому компьютеру, где открыт клиент. Порт 8006 выбирает API, 8501 — интерфейс. Если страница Streamlit обращается к API своим Python-кодом, браузер взаимодействует прежде всего со Streamlit; это отличается от отдельного JavaScript-клиента, вызывающего API напрямую.

### 5. Типичные ошибки

- Считать любой ответ сервера успешным независимо от кода.
- Использовать GET для операции «удалить все записи».
- Путать 404 с неверным паролем.
- Считать POST или значок HTTPS гарантией безопасности всего приложения.

### 6. Что запомнить

Клиент отправляет запрос, сервер возвращает ответ. Метод описывает действие, код — результат обработки. GET читает представление, POST передаёт данные для обработки. Защита канала и проверка логики приложения решают разные задачи.

## Поиск и сложность алгоритмов

Идентификатор: algorithms_01. Чтение около 4 мин; практика около 10 мин.

### 1. Поиск и размер входа

Алгоритм задаёт шаги решения задачи. Для поиска важно не только получить правильный ответ, но и понять, как затраты растут с числом элементов n. Оценка сложности описывает порядок роста, а не точное число секунд на любом компьютере.

Линейный поиск проверяет элементы последовательно. Он подходит и для неупорядоченного списка. В худшем случае придётся проверить все n элементов, поэтому время имеет линейный порядок O(n). Если нужный элемент первый, конкретный вызов завершится раньше.

### 2. Когда можно делить диапазон пополам

Двоичный поиск использует порядок элементов и возможность быстро обратиться к середине диапазона. После сравнения исключается половина кандидатов. Для обычного упорядоченного массива число сравнений в худшем случае растёт как O(log n). Если список не упорядочен по используемому сравнению, алгоритм может пропустить существующий элемент.

Перед применением нужно учесть стоимость подготовки. Однократная сортировка ради единственного поиска не всегда выгоднее линейного обхода. При большом числе запросов по почти неизменному набору её стоимость может оправдаться.

### 3. Разобранный пример

```python
def binary_search(values, target):
    left, right = 0, len(values) - 1
    while left <= right:
        middle = (left + right) // 2
        if values[middle] == target:
            return middle
        if values[middle] < target:
            left = middle + 1
        else:
            right = middle - 1
    return -1

print(binary_search([10, 20, 30, 40, 50], 40))
print(binary_search([10, 20, 30, 40, 50], 25))
```

Ответы: 3 и −1. Для числа 40 сначала рассматривается 30 на позиции 2; левая часть исключается. Затем выбирается позиция 3. Значение 25 не найдено, поэтому диапазон становится пустым. Для пустого списка цикл не выполняется и сразу возвращается −1.

### 4. Сортировка и память

Сортировка упорядочивает элементы по критерию, например имя по алфавиту или результат по убыванию. Она не обязана удалять повторения. Дополнительная память тоже часть оценки: два решения с похожим временем могут иметь разные требования к хранению.

Для данного поиска используется несколько индексов, поэтому дополнительная память O(1), без учёта входного списка. Нельзя переносить эту оценку на вариант, который на каждом шаге создаёт копию половины списка: способ реализации меняет затраты.

### 5. Типичные ошибки

- Применять двоичный поиск к неупорядоченным данным.
- Путать индекс элемента с его значением.
- Считать O(n) обещанием ровно n секунд.
- Оставлять границы неизменными и получать бесконечный цикл.

### 6. Что запомнить

Выбор алгоритма зависит от порядка данных, числа запросов, размера входа и памяти. Правильность проверяют на пустом наборе, границах, отсутствующем значении и повторениях. Скорость имеет смысл сравнивать после проверки корректности.

## Базовые структуры данных

Идентификатор: algorithms_02. Чтение около 3 мин; практика около 10 мин.

### 1. Структура под нужные операции

Структура данных определяет организацию объектов и доступные операции. Важно заранее понять, что чаще требуется: искать по ключу, брать последний добавленный элемент, обслуживать запросы по порядку или обходить связи. Один вариант не обязан быть лучшим для всех действий.

Список хранит последовательность. Словарь хранит соответствия **ключ — значение** и удобен, когда нужно получить результат по устойчивому идентификатору. Например, ключом курса может быть `python`, а значением — его название. Совпадающие имена студентов плохо подходят для уникального ключа.

### 2. Стек и очередь

Стек работает по принципу **LIFO**: последним пришёл — первым вышел. Пример — отмена последнего действия редактора. Очередь использует **FIFO**: первым пришёл — первым вышел. Она подходит для обработки ожидающих заявок в порядке поступления.

Порядок обслуживания определяется операциями, а не названием переменной. Если у списка всегда удалять последний элемент, получится стек; для очереди лучше использовать подходящую реализацию, например collections.deque, которая удобно добавляет и удаляет элементы с двух концов.

### 3. Разобранный пример

```python
from collections import deque

stack = []
stack.append("открыть файл")
stack.append("изменить заголовок")
print(stack.pop())

queue = deque(["Анна", "Борис"])
queue.append("Вера")
print(queue.popleft())

courses = {"python": "Python", "web": "Веб-технологии"}
print(courses["web"])
```

Вывод: «изменить заголовок», «Анна», «Веб-технологии». У стека осталось первое действие. В очереди после удаления находятся Борис и Вера. Словарь выбрал значение по ключу web, а не по позиции 1.

### 4. Графы связей

Граф состоит из вершин и связей, или рёбер. Вершиной может быть дисциплина, а направленным ребром — отношение «изучить прежде». Например, «деревья решений → случайный лес» задаёт направленную предпосылку. Отсутствие ребра не означает автоматически, что предметы никак не связаны: граф отражает только внесённые отношения.

Граф можно представить словарём списков соседей. Если отношения направленные, обратная связь сама не появляется. Для обхода используют выбранную стратегию и обычно отмечают посещённые вершины, чтобы не обходить цикл бесконечно.

### 5. Типичные ошибки

- Путать LIFO и FIFO.
- Удалять элемент из пустого стека без проверки.
- Считать словарь списком, индексируемым только целыми позициями.
- Забывать направление связей или посещённые вершины графа.

### 6. Что запомнить

Стек нужен для последнего действия, очередь — для очередного запроса, словарь — для соответствий по ключам, граф — для отношений. При выборе структуры сначала запишите основные операции и требуемый порядок, затем оценивайте их стоимость.

Добавьте А, Б, В сначала в стек, затем в очередь. Выпишите порядок трёх извлечений. Подберите структуру для поиска курса по id и для связей «предыдущая тема → следующая тема». Объясните опасность цикла при обходе графа.

### Ориентир для самопроверки

Стек выдаст В, Б, А; очередь — А, Б, В. Поиск по id удобно представить словарём, связи тем — графом, например словарём списков соседей. Если не отмечать посещённые вершины, цикл может привести к бесконечному повторению обхода.

## Описание набора данных

Идентификатор: statistics_01. Чтение около 4 мин; практика около 10 мин.

### 1. Одно «среднее» не описывает всё

Описательная статистика помогает кратко представить набор наблюдений. **Среднее арифметическое** равно сумме значений, делённой на их число. **Медиана** определяется по упорядоченному набору: центральный элемент при нечётном размере и среднее двух центральных при чётном. **Мода** — наиболее часто встречающееся значение; она может быть не единственной.

Эти показатели отвечают на разные вопросы. Среднее использует все численные значения и чувствительно к большим отклонениям. Медиана отражает середину упорядоченных данных и обычно устойчивее к единичным крайним значениям. Для категорий можно обсуждать моду, но среднее названий не имеет обычного числового смысла.

### 2. Разобранный набор

Пусть время выполнения задания в минутах: `2, 3, 3, 4, 18`. Сумма равна 30, среднее — `30 / 5 = 6`. Медиана — третий элемент, то есть 3. Мода тоже 3: это значение встречается дважды. Число 18 заметно тянет среднее вверх, хотя четыре участника потратили не больше четырёх минут.

Для набора `2, 3, 4, 18` медиана равна `(3 + 4) / 2 = 3,5`. Выбирать только левый центральный элемент без оговорки здесь неверно.

### 3. Измерить разброс

Два набора могут иметь одинаковое среднее и разную неоднородность. Дисперсия использует квадраты отклонений от среднего. Для полного рассматриваемого набора в этой теме делим сумму квадратов на n; для обычной несмещённой выборочной оценки используется n − 1. Нужно указывать, какая величина вычисляется.

У набора `2, 4, 6` среднее 4. Квадраты отклонений: 4, 0 и 4. Дисперсия полного набора — `8 / 3 ≈ 2,67`, выборочная оценка — `8 / 2 = 4`. Стандартное отклонение — квадратный корень из дисперсии и возвращает исходные единицы измерения.

### 4. Проверка вычислений Python

```python
from statistics import mean, median, multimode, pvariance

values = [2, 3, 3, 4, 18]
print(mean(values))
print(median(values))
print(multimode(values))
print(round(pvariance([2, 4, 6]), 2))
```

Ожидаются 6, 3, список `[3]` и 2.67. pvariance вычисляет дисперсию полного набора; её не следует молча выдавать за выборочную оценку.

### 5. Типичные ошибки

- Искать медиану до упорядочивания.
- Игнорировать пропуски, единицы измерения и размер набора.
- Смешивать формулы дисперсии с делением на n и n − 1.
- Делать вывод о «типичном студенте» только по среднему при сильных крайних значениях.

### 6. Что запомнить

Для описания данных полезно вместе указывать количество наблюдений, показатель центра и разброс. Выбор показателя зависит от типа данных и вопроса исследования. Проверяйте, не скрывает ли одно итоговое число разные ситуации.

## Вероятность и независимость

Идентификатор: statistics_02. Чтение около 4 мин; практика около 10 мин.

### 1. Событие и его вероятность

Событием называют определённый результат или набор результатов опыта. Вероятность находится от 0 до 1 включительно: невозможное событие имеет вероятность 0, достоверное — 1. Если все элементарные исходы конечного опыта равновозможны, вероятность события можно найти как долю подходящих исходов.

У честного шестигранного кубика событие «выпало чётное число» включает 2, 4 и 6. Вероятность равна `3 / 6 = 1/2`. Такое деление обосновано равновозможностью граней; для произвольного набора неодинаково вероятных исходов простой подсчёт не подходит.

### 2. Частота в наблюдениях

Относительная частота — число наблюдений события, делённое на общее число наблюдений. Если из 20 бросков чётное значение встретилось 13 раз, частота равна `13 / 20 = 0,65`. Она не обязана точно совпасть с теоретическими 0,5 в небольшой серии.

Частота зависит от конкретных данных. Повторение опыта не обязано «компенсировать» предыдущие результаты: после пяти нечётных значений следующий бросок честного независимого кубика по-прежнему имеет вероятность чётного 1/2.

### 3. Независимость и несовместность

Для независимых событий наступление одного не меняет вероятность другого. Математически `P(A и B) = P(A) × P(B)`. Например, при двух независимых бросках монеты вероятность двух орлов равна `1/2 × 1/2 = 1/4`.

Несовместные события не могут произойти одновременно. Это другое свойство: «одновременно орёл и решка в одном броске» невозможно, хотя каждый исход по отдельности имеет положительную вероятность. Такие события не являются независимыми.

### 4. Разобранный пример без случайной симуляции

```python
outcomes = [(first, second)
            for first in ("О", "Р")
            for second in ("О", "Р")]
both_heads = [pair for pair in outcomes if pair == ("О", "О")]
print(len(outcomes))
print(len(both_heads) / len(outcomes))
```

Ответы: 4 и 0.25. Перебор перечисляет все равновозможные пары двух независимых честных бросков. Он не оценивает вероятность реального события по четырём случайным наблюдениям, а рассчитывает её для заданной модели опыта.

### 5. Связь и причина

Корреляция описывает совместное изменение величин в данных. Она может возникать из-за общего фактора или особенностей отбора. Например, и число открытых материалов, и результат теста могут зависеть от предварительной подготовки. Поэтому одной связи между ними недостаточно для вывода, что увеличение кликов само по себе повысит оценку.

## Требования и контроль версий

Идентификатор: software_01. Чтение около 4 мин; практика около 10 мин.

### 1. От пожелания к требованию

Требование описывает ожидаемое поведение или ограничение системы. **Функциональное требование** отвечает на вопрос «что должна делать программа». Например: «Администратор может найти студента по части имени». Требования к скорости, доступности или другим характеристикам уточняют, насколько хорошо и в каких условиях функция должна работать.

Фраза «сделать удобно» не задаёт наблюдаемый результат. Для проверки полезны конкретный пользователь, действие, входные данные и ожидаемое состояние. Требование не обязано диктовать строку кода или цвет кнопки, если это не часть задачи пользователя.

### 2. Разобранный пример критерия приёмки

Исходное пожелание: «Нужна админка со студентами».

Проверяемая формулировка: «После успешного административного входа поиск по тексту “Белов” показывает зарегистрированных студентов, у которых эта последовательность встречается в имени или идентификаторе, без учёта регистра».

Критерии проверки:

1. До входа список недоступен.
2. В исходном наборе выбранной группы поиск «БЕЛОВ» находит того же студента, что «Белов».
3. При отсутствии совпадений показано понятное сообщение.
4. Снятие фильтра снова показывает допустимые записи.

Такой набор позволяет отличить выполненную функцию от одной только нарисованной формы.

### 3. Контроль версий

Система контроля версий хранит историю выбранных изменений файлов. Коммит фиксирует согласованное состояние с сообщением о его смысле. Он помогает сравнить редакции и понять, почему изменилось поведение. Коммит не является автоматической резервной копией всего компьютера и не заменяет запуск проверок.

Обычная последовательность работы в отдельном учебном репозитории:

```text
git status
git diff
git add lesson.md
git commit -m "Expand Python lesson with worked example"
```

Команды приведены для изучения. Их выполнение в конкретном проекте требует существующего репозитория и настроенного автора. Добавлять в историю рабочие пароли, токены и пользовательскую базу не следует: история сохраняет и старые редакции.

### 4. Разделение ответственности

Интерфейс отвечает за показ и ввод, сервер — за правила, хранилище — за записи. Когда эти обязанности разделены, изменение оформления меньше затрагивает проверку ответов. Границу модуля выбирают по смыслу, а не ради максимального числа файлов.

Например, lesson.md содержит объяснение темы; функция проверки теста сравнивает ответы; компонент страницы показывает полученный процент. Изменение абзаца не должно незаметно менять начисление баллов.

### 5. Типичные ошибки

- Формулировать требование без проверяемого результата.
- Фиксировать в одном коммите несвязанные изменения без объяснения.
- Считать наличие истории доказательством работоспособности.
- Дублировать одно бизнес-правило в нескольких независимых местах.

### 6. Что запомнить

Требование должно позволять проверить результат. Контроль версий объясняет историю изменений, а модульная структура ограничивает область их воздействия. Перед реализацией полезно записать критерий приёмки, а перед фиксацией — посмотреть различия и результаты подходящих проверок.

### Самостоятельная работа

Сформулируйте требование к поиску студентов и три критерия проверки: успешный поиск, отсутствие совпадений, запрет до входа. Предложите отдельные изменения текста урока и серверного правила. Объясните, почему их не стоит смешивать без причины.

## Проверка программного обеспечения

Идентификатор: software_02. Чтение около 4 мин; практика около 10 мин.

### 1. Что сравнивает тест

Тест задаёт известные условия, выполняет действие и сравнивает наблюдаемое поведение с ожидаемым. Без ожидаемого результата запуск программы ещё не проверяет правильность. Полезный тест обнаруживает конкретный класс ошибки, а сообщение о неудаче помогает найти причину.

Модульный тест проверяет ограниченную часть логики. Интеграционный проверяет взаимодействие компонентов, например HTTP-метода и временной базы. Проверка интерфейса рассматривает пользовательский путь. Эти уровни дополняют друг друга, потому что правильная отдельная функция ещё не гарантирует верное подключение к форме.

### 2. Разобранный пример порога

Для учебного правила «от 80 % тема освоена» проверим сам порог и соседние значения:

```python
import unittest

def is_passed(score):
    return score >= 80

class ThresholdTests(unittest.TestCase):
    def test_boundary(self):
        self.assertFalse(is_passed(79))
        self.assertTrue(is_passed(80))
        self.assertTrue(is_passed(81))

suite = unittest.defaultTestLoader.loadTestsFromTestCase(ThresholdTests)
result = unittest.TextTestRunner().run(suite)
assert result.wasSuccessful()
```

Если заменить `>=` на `>`, проверка результата 80 обнаружит ошибку. В пяти вопросах приложения реально достижимы проценты 0, 20, 40, 60, 80 и 100; значение 79 здесь используется для проверки числовой границы самой функции, а не как возможный итог такого теста.

### 3. Состояние и повторения

Для наград мало проверить одну успешную отправку. Нужно отправить тот же тест повторно: попытки должны сохраниться, а баллы за первое освоение — не начислиться снова. Это проверка поведения системы со состоянием.

Изолированная временная база позволяет воспроизводить сценарий и не менять результаты пользователей. Тесты не должны зависеть от того, какой студент первым открыл сайт сегодня. Для ошибки ввода проверяется не только код ответа, но и отсутствие нежелательной записи.

### 4. Регрессия и объём проверок

Регрессионная проверка подтверждает, что после изменения прежнее нужное поведение сохранилось. После расширения материалов важно проверить загрузку всех тем и отображение примеров. После изменения транзакции дополнительно важны повторные и параллельные запросы. Не каждый цвет кнопки требует отдельного автоматического теста.

Количество успешных тестов не доказывает отсутствие любых ошибок. Нужно понимать, какие требования и ситуации они покрывают, какие внешние сервисы действительно запускались и какие условия остались непроверенными.

### 5. Типичные ошибки

- Проверять только удобный успешный вход.
- Брать ожидаемый результат из той же функции, которую проверяют.
- Использовать рабочую базу для очищающего теста.
- Заявлять проверку всей системы по результату одного модуля.

### 6. Что запомнить

Задайте входы, состояние, действие и ожидаемый результат. Проверяйте границы и последствия ошибки. Выбирайте уровень проверки по тому, где может возникнуть нарушение, и сохраняйте сведения о фактически выполненных сценариях.

### Самостоятельная работа

Опишите проверку награды: первое успешное решение, повторное успешное решение, неверное тело запроса. Для каждого шага укажите число новых попыток и изменение баллов. Объясните, зачем нужна временная база.

### Ориентир для самопроверки

При новом профиле первое успешное решение добавляет одну попытку и 20 баллов за тест; повтор добавляет попытку и 0 баллов; недопустимый запрос не создаёт попытку и не меняет баллы. Отметка чтения здесь не выполняется. Временная база делает исходное состояние воспроизводимым и защищает рабочую историю.

## Идентификация и управление доступом

Идентификатор: security_01. Чтение около 4 мин; практика около 10 мин.

### 1. Три разных вопроса доступа

**Идентификация** сообщает, кем пользователь себя называет: например, вводится логин. **Аутентификация** проверяет это утверждение с помощью подходящего подтверждения. **Авторизация** определяет, какие операции разрешены уже распознанному пользователю. Имя admin в адресе страницы само по себе не подтверждает административных прав.

Проверка должна происходить на сервере для каждой защищённой операции. Если кнопка скрыта, но прямой запрос всё равно возвращает список студентов, ограничение не выполнено. Интерфейс объясняет состояние, а сервер обеспечивает правило.

### 2. Разобранный пример ролей

В условной учебной системе студент видит собственные результаты, преподаватель — результаты назначенных групп, администратор — управляет профилями. Даже после входа студента запрос «изменить чужую группу» должен отклоняться. Разрешение читать запись не означает разрешение редактировать её.

В нашем прототипе административные запросы требуют отдельной серверной сессии. Студенческий выбор по идентификатору остаётся демонстрационным режимом. Нельзя считать его полноценным личным кабинетом с подтверждением личности только из-за существования защищённой админки.

### 3. Пароли и второй фактор

Для хранения пользовательских паролей применяют специализированные проверочные хеши, например Argon2id, с уникальной солью. Хеширование позволяет проверить введённый пароль без хранения его исходного текста в таблице пользователей. Соль не обязана быть тайной: она помогает не получать одинаковое представление для одинаковых паролей. Обычный быстрый SHA-256 сам по себе не является подходящей заменой специализированной парольной функции.

Второй фактор добавляет независимое подтверждение, например владение устройством. Повторный ввод того же пароля не создаёт второй фактор. Готовые механизмы предпочтительнее самодельной схемы восстановления доступа.

### 4. Сессия и минимальные права

После входа сервер может выдать случайный токен ограниченного срока. Токен представляет доступ, поэтому его нельзя публиковать в отчёте или общем репозитории. Выход должен отзывать сессию, а истечение срока — прекращать её действие. HTTPS защищает передачу, но не заменяет проверку токена.

Принцип минимальных привилегий означает выдачу только необходимых прав. Если для просмотра отчёта не требуется изменение студентов, эти операции не нужно объединять в одно разрешение без причины. Проверки полезно перечислить таблицей «роль — действие — разрешено/запрещено».

### 5. Типичные ошибки

- Путать введённый логин с доказанным входом.
- Ограничивать доступ только средствами страницы.
- Хранить пользовательские пароли в общей открытой таблице.
- Передавать один бессрочный токен всем пользователям.

### 6. Что запомнить

Назвать себя, подтвердить личность и получить права — разные шаги. Проверка доступа выполняется сервером. Секреты, срок сессии, отзыв и минимальные разрешения должны рассматриваться вместе, а демонстрационный режим явно обозначаться.

Составьте матрицу прав для условных студента, преподавателя и администратора: чтение своих результатов, чтение назначенной группы, изменение профиля. Опишите, что сервер должен проверить при запросе чужих результатов. Объясните отличие второго фактора от повторного пароля.

### Ориентир для самопроверки

Студенту достаточно собственных данных, преподавателю — явно назначенных групп, администратору — необходимых административных операций. Сервер проверяет сессию, владельца или назначение и разрешение конкретного действия. Второй фактор использует независимое подтверждение; два ввода одного пароля им не становятся. Эта матрица — проектирование полной системы, не утверждение о реализации всех ролей в прототипе.

## Защита данных и безопасная работа

Идентификатор: security_02. Чтение около 4 мин; практика около 10 мин.

### 1. Что именно требуется защитить

При работе с данными различают конфиденциальность, целостность и доступность. Конфиденциальность ограничивает чтение, целостность защищает от нежелательного изменения, доступность означает возможность пользоваться данными при необходимости. Одна мера редко решает все три задачи.

Шифрование канала помогает защитить передаваемое содержимое между участниками соединения. Оно не исправляет неверный SQL-запрос, не восстанавливает удалённую базу и не делает правдивым любой текст страницы. Сначала нужно назвать конкретную угрозу, затем выбирать средство.

### 2. Разобранный сценарий фишинга

Студент получает сообщение: «Срочно подтвердите учётную запись, иначе результаты удалят», со ссылкой на похожий учебный портал. Срочность, давление и предложение ввести пароль на незнакомой странице — повод проверить запрос.

Разумная последовательность: не вводить секреты по полученной ссылке; открыть известный адрес сервиса самостоятельно; проверить уведомление через привычный канал; сообщить ответственному о подозрении. Наличие логотипа или HTTPS не доказывает принадлежность страницы учебному заведению. Адрес нужно читать целиком, а не только знакомое слово в его начале.

### 3. Резервное копирование

Копия нужна для восстановления после сбоя или ошибочного изменения. Если единственная копия находится на том же устройстве и доступна тому же вредоносному процессу, одна авария может уничтожить оба экземпляра. Полезно иметь независимое место хранения, понятный срок хранения и проверенную процедуру восстановления.

Например, перед обновлением учебной базы сохраняют согласованную копию, записывают дату и версию приложения, затем проверяют её открытие на отдельном пути. У работающей SQLite для этой задачи подходит backup API: простое чтение файла в момент записи не всегда обеспечивает нужную согласованность. Копия с персональными данными тоже требует ограничения доступа.

### 4. Обновления и секреты

Исправления безопасности закрывают известные уязвимости. Обновление сначала проверяют с учётом совместимости и возможности восстановления; бесконечное откладывание тоже оставляет риск. Версии зависимостей и результат проверки следует фиксировать.

Пароль, API-ключ или токен не должен попадать в публичный пример, скриншот либо архив исходников. Для демонстрации используют явную заглушку вроде `<TOKEN>`. Если действующий секрет опубликован, одного удаления из последней редакции недостаточно: нужно отозвать или заменить его и оценить последствия раскрытия.

### 5. Типичные ошибки

- Считать шифрование заменой резервным копиям.
- Доверять странице только из-за знакомого оформления.
- Называть файл копией, не проверив возможность восстановления.
- Публиковать секрет «ненадолго», рассчитывая удалить позднее.

### 6. Что запомнить

Защита строится из нескольких мер: проверка адреса и запросов, контроль доступа, обновления, ограничение секретов и восстановимые копии. Для каждой меры важно понимать конкретную задачу и проверять, действительно ли она выполняется.

Разберите подозрительное письмо со срочной ссылкой входа. Запишите безопасный способ проверки. Затем опишите резервную копию базы: место, дата, доступ и тест восстановления. Что делать, если действующий токен попал в публичный отчёт?

### Ориентир для самопроверки

Известный сервис открывают независимо от подозрительной ссылки, запрос подтверждают привычным каналом. Копия должна быть согласованной, доступной только нужным людям и пригодной к восстановлению на отдельном пути. Опубликованный токен отзывают или заменяют, проверяют последствия; удаления из последней редакции отчёта недостаточно.

## Адреса и сетевые устройства

Идентификатор: networks_01. Чтение около 4 мин; практика около 10 мин.

### 1. Адрес узла и путь пакета

IP-адрес используется для адресации сетевого интерфейса и доставки пакетов в IP-сетях. Он не заменяет имя пользователя и сам по себе не определяет приложение-получатель. IPv4 и IPv6 используют разные форматы адресов, но оба участвуют в сетевой доставке.

Если адрес назначения относится к другой сети, пакет обычно направляется через маршрутизатор. Маршрутизатор выбирает дальнейший путь по своей таблице маршрутов. Он не обязан знать смысл тестового вопроса или содержимое каждой передаваемой страницы.

### 2. DNS и доменное имя

DNS — распределённая система имён и записей. Среди её задач — получение адресных записей по доменному имени: например, A для IPv4 и AAAA для IPv6. Существуют и другие типы записей, поэтому определение «DNS хранит только IP-адреса сайтов» слишком узкое.

Условная последовательность открытия сайта: клиент выясняет адрес по имени, выбирает путь к нему, устанавливает нужное соединение и обменивается сообщениями приложения. Кэш может позволить повторно использовать уже полученную информацию. Сам DNS-ответ не подтверждает корректность страницы и не является шифрованием диска.

### 3. TCP и UDP

TCP предоставляет приложению упорядоченный поток байтов в установленном соединении, обнаруживает потери и использует повторную передачу. Границы отдельных записей приложения в потоке автоматически не сохраняются: формат сообщений задаёт само приложение. При неустранимом сбое соединение может завершиться ошибкой; «надёжность» не означает невозможность отказа сети.

UDP передаёт отдельные датаграммы без встроенной гарантии доставки, порядка и устранения повторов. Приложение может добавить необходимые механизмы поверх него. Поэтому ошибочно делать вывод, что любое приложение на UDP обязательно не может обеспечить надёжный обмен.

### 4. Разобранный маршрут

Представим клиента `192.0.2.10`, сервер `198.51.100.20` и логическую задачу отправить запрос. Эти диапазоны выбраны для документационных примеров. Имя сервиса помогает найти адрес; маршрутизаторы передают IP-пакеты к сети назначения; транспорт связывает обмен с приложением.

Если используется TCP, приложение читает последовательность байтов и выделяет сообщения по своему протоколу. Если используется UDP, оно получает датаграммы и решает, допустима ли потеря или нужны подтверждения. Для текущего локального сайта внешняя маршрутизация не требуется: взаимодействующие сервисы запущены на одном компьютере.

### 5. Типичные ошибки

- Путать IP-адрес с номером порта или логином.
- Считать DNS универсальным средством безопасности.
- Ожидать от UDP встроенной повторной передачи.
- Полагать, что TCP знает границы каждой записи JSON.

### 6. Что запомнить

IP решает адресацию и доставку пакетов, маршрутизатор передаёт их между сетями, DNS помогает получать записи по именам. TCP и UDP предлагают разные транспортные свойства. Формат и смысл сообщений остаются ответственностью прикладного протокола.

Опишите путь запроса к сервису по доменному имени: что даёт DNS, где нужен IP и что делает маршрутизатор. Сравните передачу двух сообщений поверх TCP с двумя датаграммами UDP. Укажите, кто выделяет границы сообщений в TCP.

### Ориентир для самопроверки

DNS возвращает записи, среди которых могут быть адресные; IP используется для сетевой доставки; маршрутизатор передаёт пакеты между сетями. TCP даёт поток байтов, и границы сообщений выделяет приложение. UDP сохраняет отдельные датаграммы, но сам не гарантирует их доставку, порядок и отсутствие повторов.

## Прикладные протоколы и соединения

Идентификатор: networks_02. Чтение около 4 мин; практика около 10 мин.

### 1. Адрес и порт

Одного адреса компьютера недостаточно, чтобы различить несколько его сервисов. Транспортный порт помогает направить обмен к нужной конечной точке. Приложения могут работать на одном узле и слушать разные порты. Адрес, транспортный протокол и номер порта рассматриваются вместе.

HTTPS обычно использует порт 443, HTTP — 80, но конфигурация может задавать другой номер. Одна только запись `:443` не включает шифрование: сервер и клиент должны действительно использовать соответствующий протокол. Локальные 8006 и 8501 в проекте выбраны для отдельных процессов, а не являются универсальными портами обучения.

### 2. Клиент, сервер и посредник

Сервер обрабатывает обращения и предоставляет сервис. Клиент инициирует нужное ему обращение. Один процесс в разных взаимодействиях может выполнять обе роли: получить запрос пользователя и затем сам обратиться к другому сервису.

Прокси выступает посредником. Входящий запрос направляется дальше, а ответ возвращается клиенту. Обратный прокси часто стоит перед приложением и может выполнять маршрутизацию, завершение TLS или другие настроенные функции. Само слово «прокси» не гарантирует анонимность, безопасность или правильность содержимого.

### 3. Разобранный пример проекта

```text
Браузер -> localhost:8501 -> Streamlit
Streamlit -> 127.0.0.1:8006 -> учебный API
Учебный API -> 127.0.0.1:8007 -> модель риска
```

Проверка модели не отправляется на порт 8501 вместо API только потому, что в браузере открыт интерфейс. Каждый процесс должен слушать свой адрес и порт. `127.0.0.1` указывает на текущий компьютер клиента этого соединения. Если открыть localhost на телефоне, он будет относиться к телефону, а не автоматически к ноутбуку с сайтом.

### 4. Последовательная диагностика

При недоступности сервиса сначала уточните адрес и порт, затем наличие процесса и то, где он слушает. После этого проверяйте локальный маршрут, правила доступа и состояние самого приложения. Ответ HTTP 404 показывает, что какой-то HTTP-сервер ответил, но ресурс не найден; отказ соединения означает другую стадию проблемы.

Для собственного локального API безопасная проверка готовности может выглядеть так:

```text
http://127.0.0.1:8006/health
```

Открытие страницы /health проверяет предусмотренный приложением маршрут. Оно не подтверждает автоматически каждый сценарий обучения, работу всех внешних сервисов или доступность с другого устройства.

### 5. Типичные ошибки

- Искать неисправность браузера, когда серверный процесс не запущен.
- Путать адрес сервиса с адресом документации другого сервиса.
- Ожидать, что localhost на разных устройствах обозначает один компьютер.
- Считать любой успешно открывшийся маршрут полной проверкой приложения.

### 6. Что запомнить

Порт различает сервисы, протокол определяет правила обмена, а роль клиента или сервера относится к конкретному взаимодействию. При диагностике двигайтесь от процесса и адреса к ответу приложения, фиксируя наблюдаемые факты.

### Ориентир для самопроверки

Интерфейс — 8501, API — 8006, модель — 8007. Loopback относится к устройству, выполняющему клиентское соединение. Отказ соединения требует проверки процесса, адреса и порта; 404 означает, что HTTP-сервер уже ответил, но запрошенный ресурс не найден.

## Процессы и ресурсы

Идентификатор: os_01. Чтение около 4 мин; практика около 10 мин.

### 1. Программа и процесс

Программа может храниться как файл с инструкциями, а **процесс** — это экземпляр её выполнения с ресурсами. Два запуска одной программы могут создать разные процессы со своей памятью и состоянием. Идентификатор процесса помогает операционной системе различать эти экземпляры.

ОС управляет процессорным временем, памятью, файлами и другими ресурсами. Приложение обращается к предоставленным интерфейсам, а не получает безусловный доступ ко всем данным компьютера. Факт наличия файла программы не доказывает, что процесс сейчас запущен.

### 2. Потоки и планировщик

Поток — последовательность выполнения внутри процесса. Потоки одного процесса обычно разделяют адресное пространство и часть ресурсов, при этом имеют собственные стеки выполнения. Общая память упрощает передачу данных, но требует согласования при изменении.

Планировщик определяет, какие готовые задачи получают процессорное время. Даже на одном ядре несколько задач могут продвигаться за счёт переключений; это не обязательно означает физически одновременное выполнение всех инструкций. На нескольких ядрах возможен параллелизм.

### 3. Память и сохранение

Оперативная память хранит код и данные работающих программ. Состояние в памяти не следует считать постоянным: завершение процесса обычно лишает приложение этих временных значений. Для восстановления после перезапуска нужные результаты сохраняют в подходящем долговременном хранилище.

В нашем сайте временный раскрытый разбор находится в сеансе Streamlit, а попытки тестов записаны в SQLite. Поэтому история может восстановиться после обновления страницы, даже если конкретное состояние открытого блока не сохранилось. Нельзя обещать такую же устойчивость данным, которые существовали только в переменной Python.

### 4. Разобранный конфликт записи

Пусть два запроса хотят начислить одну награду. Оба читают «ещё не начислена», затем каждый добавляет 20 баллов. Если проверка и запись не согласованы, получится 40 вместо 20.

В базе проблему решают подходящая транзакция и уникальное ограничение, например на сочетание «студент — тип действия — тема». Только одна операция создаёт запись завершения; вторая получает уже существующий результат. Защита кнопки от повторного нажатия полезна для удобства, но не заменяет серверную согласованность.

### 5. Как наблюдать процесс

Обычно изучают идентификатор, команду запуска, загрузку ресурсов и журнал. Завершать неизвестный процесс только из-за похожего имени опасно для чужой работы. В учебном проекте менеджер останавливает процессы, принадлежность которых проверена по пути запуска.

### 6. Типичные ошибки и вывод

- Считать программу на диске и её работающий процесс одним состоянием.
- Ожидать сохранности переменных после завершения процесса.
- Изменять общую память или запись без согласования.
- Принимать отсутствие окна за отсутствие фонового процесса.

Процесс представляет выполнение, поток — путь выполнения внутри него. ОС распределяет ресурсы, а приложение должно явно обеспечить сохранение и согласованность важных данных.

Почему закрытие вкладки не обязано останавливать API? Какие результаты нужно сохранить для восстановления после перезапуска? Опишите гонку двух запросов на одну награду и способ предотвратить повторную запись.

### Ориентир для самопроверки

Вкладка и серверный процесс имеют разные жизненные циклы. Попытки и завершения должны храниться долговременно; временный открытый блок может остаться только в сеансе. ## Файлы и права доступа

Идентификатор: os_02. Чтение около 4 мин; практика около 10 мин.

### 1. Путь к объекту

Файловая система организует данные в файлы и каталоги. Каталог может содержать другие каталоги, образуя дерево. **Абсолютный путь** задаёт расположение от корня или выбранного диска; **относительный** зависит от текущего каталога процесса.

Например, `docs/lesson.md` указывает на разный объект при запуске из разных папок. Программа, которой нужен файл рядом с собственным модулем, может вычислять путь относительно расположения модуля. Текущий каталог запуска и каталог исходного файла не обязаны совпадать.

### 2. Права и формат

Права определяют разрешённые операции, например чтение, запись и выполнение. Владение файлом и право его прочитать — связанные, но разные характеристики. Операционная система и используемая файловая система задают конкретную модель доступа; правила Unix нельзя без проверки переносить на все системы.

Расширение имени, например .json или .png, помогает предположить формат, но не проверяет байты. Переименование текстового файла в изображение не превращает его содержимое. Обработчик должен проверять ожидаемую структуру и сообщать об ошибке.

### 3. Разобранный пример Python

```python
from pathlib import Path
from tempfile import TemporaryDirectory
import json

with TemporaryDirectory() as directory:
    root = Path(directory)
    report = root / "report.json"
    report.write_text('{"score": 80}', encoding="utf-8")
    data = json.loads(report.read_text(encoding="utf-8"))
    print(report.name)
    print(data["score"])
```

Результаты: `report.json` и 80. Файл создаётся внутри отдельного временного каталога. Операции записи, чтения и разбора JSON здесь различаются: успешное чтение текста ещё не означает корректный JSON. После выхода из блока временный каталог удаляется библиотекой, поэтому этот пример не предназначен для постоянного отчёта.

### 4. Копия перед изменением

Перед значимым изменением сохраняют проверяемую копию. Для обычного закрытого текстового файла это может быть отдельная копия с датой. Для работающей базы требуется согласованный способ, предусмотренный её системой. Восстановление следует проверять на другом пути, чтобы не затереть действующие данные.

Приложению полезно различать «нет файла», «нет права чтения» и «неверное содержимое». Эти случаи требуют разных исправлений. Автоматически создавать пустую базу при любой ошибке доступа опасно: это может скрыть неверно заданный путь.

### 5. Типичные ошибки

- Считать относительный путь независимым от места запуска.
- Применять операции ко всей папке, не проверив точный путь.
- Доверять формату только по расширению.
- Перезаписывать важный файл без возможности восстановления.

### 6. Что запомнить

Каталоги организуют объекты, путь задаёт их расположение, права — допустимые операции, а формат определяет содержимое. Для надёжной работы нужны явные пути, понятная обработка ошибок и проверенное восстановление важных данных.

### Самостоятельная работа

Объясните, как меняется смысл docs/lesson.md при смене текущего каталога. В отдельном временном каталоге создайте JSON, прочитайте его и получите поле score. Опишите отдельно ошибки отсутствия файла, прав чтения и неверного JSON.

### Ориентир для самопроверки

Относительный путь вычисляется от текущего каталога процесса. Пример конспекта использует явный root временного каталога и UTF-8. Отсутствие файла исправляется проверкой расположения, запрет чтения — прав, неверный JSON — содержимого. Переименование расширения ни одну из этих причин автоматически не устраняет.
