# Адаптивная система дистанционного обучения с элементами геймификации

Рабочий учебный прототип на Python, FastAPI, Streamlit и SQLite. Две учебные группы по 15 вымышленных студентов, по восемь дисциплин в учебном плане. Всего десять дисциплин, 22 темы и 110 вопросов; рекомендации по результатам, история, баллы, уровни и достижения. Есть защищённая админка со всеми зарегистрированными студентами, фильтрами, карточками, добавлением, редактированием и архивацией. Экран «Сегодня» показывает рекомендованный урок, причину выбора и доступный XP. Меню слева открывает урок, маршрут, награды, историю прогресса, учебный план и аналитику. Прогресс можно выгрузить в CSV и JSON.

## Подробное руководство

Полная структура проекта, назначение файлов и функций, методы API, таблицы базы, алгоритмы и инструкции по изменению находятся в `docs/Полное_описание_проекта.md` и одноимённом PDF. Иллюстрации расположены рядом в `docs/скриншоты`.

## Запуск на текущем компьютере

Откройте `ЗАПУСТИТЬ.cmd`. Он запускает приложение в установленной Ubuntu WSL и открывает браузер. Docker для основного сценария не нужен.

- Интерфейс: http://localhost:8501
- Документация API: http://localhost:8006/docs
- Сервис модели OULAD: http://localhost:8007/docs

Запуск использует существующее окружение `/home/hxrdbvss/miniconda3/envs/mlops-lab/bin/python`. Исходный проект в домашней папке Ubuntu не изменён. Работает копия из текущей папки Windows.

Команды из Ubuntu, находясь в этой папке:

```bash
/home/hxrdbvss/miniconda3/envs/mlops-lab/bin/python manage_demo.py start
/home/hxrdbvss/miniconda3/envs/mlops-lab/bin/python manage_demo.py status
/home/hxrdbvss/miniconda3/envs/mlops-lab/bin/python manage_demo.py stop
```

Журналы находятся в `.runtime`. Занятые чужими процессами порты автоматически не освобождаются. Если предыдущий запуск завершился частично, сначала выполните `stop`, затем `start`.

## Запуск в другом Python окружении

Проверено на Python 3.10 и версиях из `requirements-demo.txt`. Для запуска в подготовленном окружении установите зависимости и выполните:

```bash
python -m pip install -r requirements-demo.txt
python manage_demo.py start
```

Менеджер процессов рассчитан на Linux/WSL. На Windows без WSL запускайте сервисы вручную в трёх терминалах из корня проекта:

```text
python -m uvicorn unified_api:app --app-dir knowledge-project --host 127.0.0.1 --port 8006
python -m uvicorn risk_api:app --app-dir coursework-data/oulad --host 127.0.0.1 --port 8007
python -m streamlit run knowledge-project/student_portal.py --server.address 127.0.0.1 --server.port 8501 --server.headless true
```

Новый запуск в чистом окружении отдельно не проверялся. Рядом с моделью должны оставаться `models/day30_logistic.joblib` и `results/day30_logistic_test.json`.

## Сценарий студента

1. Укажите новый идентификатор, например `student_show_01`.
2. Изучите первую тему и отметьте материал изученным: начислится 10 баллов.
3. Пройдите тест. Менее 50 % означает повторение; 50–79 % — дополнительную практику; от 80 % — освоение темы.
4. За первое успешное прохождение теста начисляется 20 баллов. Повторные успешные попытки сохраняются, но повторных баллов не дают.
5. Перейдите к следующей рекомендованной теме. В разделе «Мой прогресс» видна история попыток, а условия достижений и уровень собраны в разделе «Награды».

Отметка о чтении не заменяет тест. Освоение темы определяется лучшим результатом от 80 %; неудачная повторная попытка не отменяет уже подтверждённое освоение. Персональная рекомендация учитывает конкретные ошибки, последние попытки, предпосылки и сроки повторения; выбор других тем остаётся доступным.

Идентификатор можно задать ссылкой: http://localhost:8501/?student=student_show_01. Учебный кабинет остаётся демонстрационным входом по id. Администратор входит по отдельному паролю; его операции защищены серверной сессией.

## Группы, датасет и админка

В боковой панели раскройте «Выбрать демостудента». ПИ-21 и ИВТ-21 содержат по 15 студентов, шесть общих дисциплин и по две профильных. Выбранный курс доступен в списке «Дисциплина» и в разделе «Учебный план». Счётчики тем и попыток раздельные, опыт и уровень общие.

Админка: http://localhost:8501/?view=admin. Логин `admin`, автоматически созданный пароль — в `.runtime/admin_access.txt`. Файл появляется при запуске API и исключён из архива. Можно задать свой пароль через `LEARNING_ADMIN_PASSWORD` перед запуском. Сессия действует восемь часов, выход отзывает её.

Датасет CSV/JSON находится в `datasets/academy_demo`, описание полей — в его README. Все имена и результаты вымышлены; модель OULAD на них не обучалась. Данные импортируются один раз без сброса существующей истории. При добавлении студентов через админку изменяется SQLite; актуальный список скачивается из интерфейса.

Подробный сценарий с иллюстрациями: `docs/Как_проверить_группы_и_админку.md`. Новые модули: `knowledge-project/academy_core.py` и `academy_portal.py`.

## Учебные материалы

Все 22 темы расширены: теория, разобранные примеры, типичные ошибки, самостоятельное задание, ориентир и ссылки на источники. В интерфейсе можно скачать конспект текущей темы. Полный сборник — `docs/Учебные_материалы.md`, редактируемые исходники — `learning-content/*.md`, метаданные — `learning-content/catalog.json`.

После правки исходников выполните `python datasets/build_lessons.py` из корня и обновите страницу. Генератор академического набора также вызывает эту сборку, поэтому повторная генерация не убирает развёрнутые материалы. Прогресс и ключи вопросов остаются прежними. Задания для самостоятельной работы не проверяются автоматически; освоение подтверждается отдельным тестом.

Проверка примеров из корня: `python knowledge-project/verify_lesson_content.py`. Подтверждены 63 проверки содержания и выгрузок, включая выполнение 11 Python-примеров и запросов SQL в изолированных условиях.

## Индивидуальная адаптация

Система диагностирует ошибки по 110 понятиям, показывает конкретные упражнения и фрагменты конспекта, учитывает последние попытки и граф предпосылок. После успешного теста назначается повторение через 3, 7 или 14 дней. Историческое освоение и награды сохраняются; у рекомендации всегда есть объяснение.

Одинаковые 60 % у `adaptive_demo_a` и `adaptive_demo_b` приводят к разным заданиям. Для создания примеров на новом запуске выполните `python prepare_adaptive_demo.py` из knowledge-project. Третий профиль `adaptive_demo_prerequisite` показывает возврат к основе при затруднении в лесе. История уже существующих профилей не сбрасывается.

Полная инструкция: `docs/Адаптивность_и_проверка.md`. Движок основан на объяснимых правилах; оценки по ответам не являются вероятностью знания. Подбор новых вопросов по сложности и автоматическая проверка свободных ответов пока отсутствуют.

## Проверки

Из папки `knowledge-project`:

```bash
python -m unittest test_learning_flow test_portal_exports test_academy test_adaptive_engine -v
python verify_running_demo.py
python verify_academy_ui.py
python verify_adaptive_ui.py
```

Первая команда выполняет 33 изолированных теста ядра, доступа, выгрузки и адаптивной логики. Три сценария после неё требуют запущенные сервисы: 23 проверки обучения с моделью OULAD, 20 проверок учебных планов и админки и 17 проверок индивидуальных маршрутов. Отчёты — `project_results/current_demo_validation.json` и `current_academy_validation.json`. Дополнительные тесты RAG, Docker и Neo4j требуют отдельных сервисов.

## Основные файлы

- `knowledge-project/student_portal.py` — точка входа интерфейса.
- `knowledge-project/portal_app.py` — страницы, формы и обращения к API.
- `knowledge-project/portal_ui.py`, `knowledge-project/assets/portal.css` — компоненты оформления и стили.
- `knowledge-project/learning_core.py` — тестирование, траектория и прогресс.
- `knowledge-project/unified_api.py` — общий API и интеграция модели.
- `knowledge-project/material_content.json`, `quizzes.json` — материалы и задания.
- `knowledge-project/learning_progress.db` — действия и попытки тестов.
- `graph-db-lab/learning_materials.csv` — порядок и метаданные четырёх тем.
- `coursework-data/oulad` — подготовка данных, модель риска и сохранённые метрики.

## Дополнительные исследовательские модули

Предыдущие модули RAG, ChromaDB и Neo4j сохранены. Их endpoints `/ask`, `/ask-manual`, `/adaptive-recommendation` требуют отдельных сервисов и соответствующего окружения. Их старый запуск описан в `knowledge-project/README_START.md`. В текущую проверку основного сценария они не входят.

Модель OULAD работает отдельно от адаптации по тестам. Перенос её прогноза на результаты этого курса не оценивался. Сохранённые метрики описывают прежние эксперименты OULAD, а не новое педагогическое исследование.
