### 1. Запрос и ответ

В клиент-серверной модели клиент обращается к сервису, сервер обрабатывает запрос и формирует ответ. Браузер часто выступает клиентом, но запрос может отправлять и другая программа. HTTP описывает обмен сообщениями прикладного уровня: метод, адрес ресурса, заголовки и, при необходимости, тело.

Ответ содержит код состояния, заголовки и необязательное тело. Тело может быть HTML-страницей, JSON, изображением или другим представлением. Сервер не обязан отвечать страницей только потому, что запрос отправлен из браузера.

### 2. Методы и состояния

GET обычно получает представление ресурса и по своему смыслу не должен выполнять запрошенное изменение данных. POST отправляет данные для обработки, например ответы теста. Метод выбирают по смыслу операции, а не по длине адреса. POST сам по себе не защищает пароль и не шифрует тело запроса.

Код 200 обычно означает успешную обработку, 201 — создание ресурса, 404 — отсутствие запрошенного ресурса. Код 401 связан с отсутствующей или неподходящей аутентификацией, 403 — с запретом доступа. Ошибки класса 5xx относятся к обработке на стороне сервера. Конкретный API должен документировать свои состояния.

### 3. Разобранный обмен

Условный запрос тестовых вопросов:

```http
GET /quiz/python_01 HTTP/1.1
Host: localhost:8006
Accept: application/json
```

Успешный ответ может содержать:

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"material_id": "python_01", "questions": []}
```

Пустой список здесь сокращает пример сообщения: в работающем приложении вопросы заполнены. Для отправки решения используется другой запрос, POST, с идентификатором студента и массивом выбранных индексов. Процент вычисляет сервер; клиент не должен объявлять собственный результат достоверным.

### 4. Канал и содержимое

HTTPS использует TLS для защиты обмена между конечными точками соединения, включая шифрование и проверку сертификата в обычной веб-модели. Это не доказывает честность владельца страницы и не исправляет ошибки его программы. Поддельный сайт тоже может иметь HTTPS.

В локальной демонстрации адрес localhost относится к тому компьютеру, где открыт клиент. Порт 8006 выбирает API, 8501 — интерфейс. Если страница Streamlit обращается к API своим Python-кодом, браузер взаимодействует прежде всего со Streamlit; это отличается от отдельного JavaScript-клиента, вызывающего API напрямую.

### 5. Типичные ошибки

- Считать любой ответ сервера успешным независимо от кода.
- Использовать GET для операции «удалить все записи».
- Путать 404 с неверным паролем.
- Считать POST или значок HTTPS гарантией безопасности всего приложения.

### 6. Что запомнить

Клиент отправляет запрос, сервер возвращает ответ. Метод описывает действие, код — результат обработки. GET читает представление, POST передаёт данные для обработки. Защита канала и проверка логики приложения решают разные задачи.
