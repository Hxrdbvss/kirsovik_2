### 1. Узлы, ветви и листья

**Дерево решений** последовательно проверяет условия над признаками объекта. Начальный узел называется корнем. Внутренний узел задаёт проверку, ветви соответствуют её исходам, а конечный узел — **лист** — содержит предсказание. Путь от корня до листа можно прочитать как цепочку правил «если …, то …».

Деревья применяются и для классификации, и для регрессии. В первом случае лист задаёт класс или оценки вероятностей классов, во втором — числовой прогноз. Набор правил, написанных вручную, помогает понять устройство дерева, но обучаемая модель подбирает разбиения по примерам.

### 2. Как выбираются условия

Во время обучения алгоритм перебирает допустимые разбиения. Для классификации оценивается, насколько группы после разбиения становятся более однородными по ответам. Например, условие по числу выполненных заданий полезно, если после него лучше отделяются разные классы. Процесс повторяется внутри получившихся частей, пока не сработает условие остановки.

Узлы не обязаны проверять разные признаки: один числовой признак может использоваться несколько раз с разными порогами. Глубина дерева показывает длину пути от корня к наиболее далёкому листу. Очень глубокое дерево может запоминать редкие особенности обучающих записей.

### 3. Разобранный пример

Пусть демонстрационное правило использует число заданий и последний процент теста:

```python
def recommendation(tasks, score):
    if tasks < 3:
        return "повторить основы"
    if score < 80:
        return "выполнить практику"
    return "перейти дальше"

print(recommendation(2, 90))
print(recommendation(4, 60))
print(recommendation(4, 100))
```

Ответы: «повторить основы», «выполнить практику», «перейти дальше». Первый объект не проверяет условие по проценту: он сразу попадает в лист первой ветви. Изменение неиспользованного признака на этом пути не меняет ответ. Этот пример иллюстрирует обход дерева; условия здесь выбраны вручную и не являются обученной моделью.

### 4. Сложность и переобучение

Дерево с отдельным листом почти для каждого примера может показать прекрасный результат на обучении и ошибаться на новых данных. Ограничение максимальной глубины и минимального числа объектов в листе уменьшает сложность. Слишком сильное ограничение, наоборот, может не позволить уловить полезные закономерности — это недообучение.

Настройки сравнивают на валидационных данных. После выбора решения качество оценивают на отдельной тестовой выборке. Нельзя объявлять определённую глубину «лучшей для всех задач» без проверки.

### 5. Типичные ошибки

- Считать лист ещё одним вопросом: в листе уже формируется ответ.
- Полагать, что большая глубина всегда повышает качество на новых данных.
- Путать ручную схему решений с моделью, обученной по примерам.
- Настраивать дерево много раз по итоговой тестовой выборке.

### 6. Что запомнить

Узел проверяет условие, ветвь выбирает направление, лист выдаёт предсказание. Ограничение глубины помогает контролировать сложность. Полезность условий и настроек подтверждается на новых данных, а не внешним видом дерева.
