### 1. Адрес узла и путь пакета

IP-адрес используется для адресации сетевого интерфейса и доставки пакетов в IP-сетях. Он не заменяет имя пользователя и сам по себе не определяет приложение-получатель. IPv4 и IPv6 используют разные форматы адресов, но оба участвуют в сетевой доставке.

Если адрес назначения относится к другой сети, пакет обычно направляется через маршрутизатор. Маршрутизатор выбирает дальнейший путь по своей таблице маршрутов. Он не обязан знать смысл тестового вопроса или содержимое каждой передаваемой страницы.

### 2. DNS и доменное имя

DNS — распределённая система имён и записей. Среди её задач — получение адресных записей по доменному имени: например, A для IPv4 и AAAA для IPv6. Существуют и другие типы записей, поэтому определение «DNS хранит только IP-адреса сайтов» слишком узкое.

Условная последовательность открытия сайта: клиент выясняет адрес по имени, выбирает путь к нему, устанавливает нужное соединение и обменивается сообщениями приложения. Кэш может позволить повторно использовать уже полученную информацию. Сам DNS-ответ не подтверждает корректность страницы и не является шифрованием диска.

### 3. TCP и UDP

TCP предоставляет приложению упорядоченный поток байтов в установленном соединении, обнаруживает потери и использует повторную передачу. Границы отдельных записей приложения в потоке автоматически не сохраняются: формат сообщений задаёт само приложение. При неустранимом сбое соединение может завершиться ошибкой; «надёжность» не означает невозможность отказа сети.

UDP передаёт отдельные датаграммы без встроенной гарантии доставки, порядка и устранения повторов. Приложение может добавить необходимые механизмы поверх него. Поэтому ошибочно делать вывод, что любое приложение на UDP обязательно не может обеспечить надёжный обмен.

### 4. Разобранный маршрут

Представим клиента `192.0.2.10`, сервер `198.51.100.20` и логическую задачу отправить запрос. Эти диапазоны выбраны для документационных примеров. Имя сервиса помогает найти адрес; маршрутизаторы передают IP-пакеты к сети назначения; транспорт связывает обмен с приложением.

Если используется TCP, приложение читает последовательность байтов и выделяет сообщения по своему протоколу. Если используется UDP, оно получает датаграммы и решает, допустима ли потеря или нужны подтверждения. Для текущего локального сайта внешняя маршрутизация не требуется: взаимодействующие сервисы запущены на одном компьютере.

### 5. Типичные ошибки

- Путать IP-адрес с номером порта или логином.
- Считать DNS универсальным средством безопасности.
- Ожидать от UDP встроенной повторной передачи.
- Полагать, что TCP знает границы каждой записи JSON.

### 6. Что запомнить

IP решает адресацию и доставку пакетов, маршрутизатор передаёт их между сетями, DNS помогает получать записи по именам. TCP и UDP предлагают разные транспортные свойства. Формат и смысл сообщений остаются ответственностью прикладного протокола.
